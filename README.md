# 게이트비젼 챗봇 운영 리포트

## 실행

Node.js 20.9 이상과 npm을 사용합니다. 의존성 패키지의 Node 요구 사항도 충족하는 버전을 선택합니다.

```sh
npm ci
cp .env.example .env.local
npm run dev
```

개발 서버를 시작하기 전에 .env.local에 Supabase URL과 서버 전용 서비스 역할 키를 설정합니다. APP_SECRET_KEY에 별도 난수를 설정하면 세션 서명에 우선 사용하며, 키를 바꾸면 기존 사용자는 다시 로그인해야 합니다.

```sh
npm test
npm run lint
npm run build
```

## 조회 및 반출

보고 서버는 faq_history의 occurred_at을 한국 현지 시각으로 읽습니다. 조회 기간과 브랜드를 먼저 적용하고 문의를 여러 페이지로 읽어 하나의 결과를 만듭니다. SUPABASE_HISTORY_TABLE로 호환 스키마의 이력 테이블을 지정할 수 있습니다. 화면의 표시 건수는 최근 질문·로그와 순위 목록에 적용합니다.

고객 행동 지표는 조회 기간 내 식별 고객 수, 한 번만 문의한 식별 고객 수, 상담원 관련 표현을 포함한 질문 수를 사용합니다. 최근 7일·30일 미매칭 횟수는 선택한 기간에 포함된 문의를 종료일 기준으로 계산합니다. 종료일을 비우면 한국의 오늘이 기준입니다.

반출 데이터에서는 고객 질문에 포함된 이메일·국내 전화번호·주민등록번호 형식을 가립니다. 자유 입력 내용은 공유 전 확인해야 합니다. 다운로드 감사 API는 기존 gatevision.download_audit_logs 테이블을 사용합니다.

## DB 적용

DB 설치·권한 변경 스크립트는 운영 담당자가 별도로 관리합니다. 새 Supabase 환경에서는 별도 제공되는 sql/history_sql.sql을 사용합니다. 기존 환경의 권한 변경에는 sql/restrict_report_access.sql을 사용합니다. 적용 전 외부 챗봇 수집기가 서버 전용 자격 증명으로 기록하는지 확인합니다. 대시보드·메일의 기간 집계는 기존 이력 테이블에서 동작합니다.

## 일일 메일

Vercel의 기존 예약 시각은 한국 시간 매일 오전 9시이며, 전날 00시부터 당일 00시 직전까지의 문의를 보고합니다. CRON_SECRET을 설정하고 배포하면 예약 GET이 인증됩니다. 수동 POST는 활성 상태의 report 서비스 admin 계정이 사용할 수 있습니다.

REPORT_RECIPIENT_EMAIL로 수신자를 지정하고 RESEND_API_KEY 또는 기존 SMTP 설정으로 메일을 발송합니다. 조회 권한과 관리자 권한은 중요 API 요청마다 Supabase 계정의 현재 설정으로 확인합니다.
